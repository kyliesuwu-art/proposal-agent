# 项目规格

## 1. 产品目标

这是一个内部验证项目：基于用户需求和本地知识库生成一份带证据引用的 `proposal.md`，再由独立本地渲染器从已验证的交付材料派生 DOCX 或 PPTX。它不是多用户平台、高并发服务或复杂编排系统。

## 2. 核心流程

`用户需求 → LLM 大纲 → retrieve_evidence() → 分章写作 → 审查/修订 → 已验证 proposal.md → 下游 Word/PPT 渲染`

`proposal.md` 是唯一方案内容源。大纲、证据映射和审查任务是内存执行状态，不创建章节文件、draft/final 双文件、`plan.json`、`audit.json` 或工作区数据库。DOCX/PPTX 不得决定来源事实或方案内容。

## 3. 检索与证据规则

- 检索结合 Chroma 语义搜索、SQLite FTS5 词法搜索、确定性 RRF 和 supporting pages；`retrieve_evidence()` 不生成答案。
- 来源必须以可移植文档身份以及真实文件名、页码持续可追溯；不得持久化机器绝对路径。
- LLM 只能使用程序提供的证据 ID 和图片 ID；由确定性代码解析。
- 有证据的技术事实和参数必须引用。无证据内容使用 `【待确认】`；用户输入仍是用户输入，不得充当知识库来源。
- 政策、案例、产品能力和标准分别是参考、案例、可选能力或待确认适用性，不能写成已确定项目事实或承诺。

## 4. Markdown 方案规则

- 写作与修订过程中保留原始 `[S#]` / `[IMG#]` ID，仅在发布时解析。
- 用户明确的交付项必须在标题层级中可识别；合理归并时使用明确 H3。
- 不引入固定 DOCX 模板、整篇手写 OOXML、LangGraph、多智能体框架或方案状态机。
- Markdown 交付同时发布稳定的溯源侧车。

## 5. 图片规则

- 图片只能来自真实检索结果。不得编造路径、文件名、页码、图注或描述。
- 交付图片必须是独立 Markdown 图片块，具有有意义的单行图注和安全相对路径。
- 仅复制实际使用的图片到 `proposal.md` 同级的 `assets/image-###.<ext>`；Markdown 仅引用该稳定路径。
- 无效、行内、孤立、缺少有效上下文图注、未知 ID、重复或缺失的图片资产，必须由受控发布流程拒绝或处理，不能静默发布。

## 6. Word 与 PPT 交付规则

- 审阅 Markdown 展示证据和待确认信息。正式 Word/PPT 是只读派生物，页面可见文本不含引用/来源 ID、内部 ID、草稿/状态标签或图片来源标签。
- 溯源保留在侧车、计划、报告和来源资料中；正式页面干净不等于丢弃溯源。
- 未知输入保留为具体的“深化设计输入条件”，不得改写为事实。
- 正式 PPT briefing 为 15–25 页，通常约 18–20 页。内容组织/Thinking 可以改善叙事、重点和版式，但不得创造事实、参数或图片路径。
- 只使用相关图片；每页优先一个清晰观点和可读正文。详细 PPT 视觉约定见 `config/PPT_GENERATION_GUIDE.md` 与 `config/PPT_VISUAL_DESIGN_GUIDE.md`。

## 7. 质量门禁

正式审阅 Markdown 写盘前，确定性验证要求：首位且唯一的合法 H1、有效标题语法、用户要求标题覆盖、无内部 ID/cache/绝对路径、引用和来源列表一致、图片资产存在、待确认项具体且非空。失败必须报告阶段，不能标记成功或进行无界 LLM 修补。

Office 交付检查可验证文件结构、媒体、可见文本泄露、页数范围和几何边界，但不能替代逐页视觉审阅。没有真实渲染页检查时，视觉状态必须是 `BLOCKED` 或 `NOT_RUN`，不能是 `PASS`。

## 8. 数据与外部服务安全

- 当前唯一测试数据库是 `runtime_data/word_test_db`，collection 为 `electrical_pages_v2`。默认不得搜索、恢复或重建已删除的 `v2_test_db`、`v3_candidate_db`、`v3_candidate_db_rebuilt`。
- 未经明确授权，不得删除、移动、重建、覆盖或写入数据库、缓存和客户资料。
- SQLite 以 URI `mode=ro` 检查。先确认路径存在；Chroma 验证必须使用完整临时副本，因为 `PersistentClient` 可能维护文件。
- 测试默认使用 fake LLM/fake retriever 和临时目录。未经明确授权不得调用 DashScope、embedding、MinerU、企微或其他外部服务。
- 不得在持久化元数据中暴露密钥、令牌、敏感客户数据或机器绝对路径。

## 9. Git 与实验边界

保留现有工作树改动。未经明确授权不得执行破坏性 Git 操作。实验输出及其临时结论属于实验报告和 Git 历史；与当前任务无关的在开发 renderer 或实验不得被改动。

## 10. 信息归属

Spec 描述系统应该做什么；Tests 自动保证可量化不变量；`DECISIONS.md` 记录为何作出长期架构选择；Git 历史和报告保留实现与实验过程。
